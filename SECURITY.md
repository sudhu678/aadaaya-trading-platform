# Security Policy

## Reporting vulnerabilities

Please do not publicly disclose exploitable security issues before maintainers have had a chance to address them. Use GitHub's private vulnerability reporting feature if enabled; otherwise contact the maintainers through a private channel listed in the repository once published.

## Sensitive data

Never commit credentials, API tokens, `.env`, private keys, personal portfolio databases, trade histories, caches, or private implementation files. Rotate any credential that has been exposed.

## Trading safety

Do not enable real-order execution without explicit configuration, appropriate safeguards, and independent testing. Example trading logic is not production investment guidance.

## Supported versions

Security support policy will be defined when the first public release is tagged.
